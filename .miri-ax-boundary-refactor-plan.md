# Temporary AX Boundary Refactor Plan

Status: implementation in progress after a second pre-async behavioral review found additional regressions; repairs, verification, repackaging, and manual acceptance remain. This plan must remain in the repository until implementation, automated verification, packaging, manual testing, and explicit user acceptance are complete.

## Completion rule

This work is **not complete** when the code builds or when a package is produced. It is complete only after:

1. Every implementation and verification item below is complete.
2. A rebuilt `dist/Miri.app` and DMG are provided for manual testing.
3. The user manually validates the acceptance scenarios below.
4. The user explicitly confirms acceptance.
5. Only after that confirmation, this temporary plan is deleted and final debug/release/package verification passes.

## Review findings

### Active synchronous target-app IPC outside the AX executor

- Normal termination restoration calls synchronous AX frame writes on the main actor through `LayoutWindowSystemAdapter.setFrame` and `LayoutController.restoreForTermination`.
- The cleanup-watcher process directly and serially reads `AXWindows` for every regular application and writes matching frames.
- AX observer handling calls private `_AXUIElementGetWindow` on the main actor through `SkyLight.shared.windowID(for:)` before submitting created/moved/resized work to a PID lane.

### Restoration regressions found during the audit

- `Miri.writeRestoreSnapshot(viewport:)` has no caller, so crash/forced-exit restoration normally has no current restoration document.
- Cleanup restoration unions tiled and floating IDs and applies the viewport frame to both; floating windows should retain their geometry.
- Normal termination ignores AX restoration errors and unconditionally removes the restore document and stops the cleanup watcher.
- Termination does not globally quiesce every AX lane before direct restoration, so a late queued frame write can undo exit restoration.
- Cleanup restoration scans applications serially, allowing one unrelated hung PID to delay healthy-window restoration.

### Focus-adoption regression reported during implementation

- Cmd-Tab activation can physically focus a managed window without revealing or projecting its logical Miri column.
- Focus adoption currently projects only when the logical workspace/column identity changes. If the target is already the logical active window but its camera projection is stale or parked, activation changes macOS focus without moving the layout to it.
- Activation-settle reconciliation must preserve lifecycle-only ordering while a separately frontmost-validated focus read authoritatively reveals and projects the activated window.

### Startup discovery regression reported during manual testing

- Starting the packaged app did not construct a layout from existing windows.
- Root cause: the chunked `AXApplicationReadPipeline` was captured weakly by its enumeration and chunk callbacks without another owner. It deallocated after submitting `AXWindows`, so successful enumeration never advanced into window-snapshot chunks and the full-scan barrier never completed normally.
- The pipeline must remain strongly retained across enumeration and every chunk, then release after exactly one success/failure completion.

### Additional regressions found by the pre-async behavioral review

- A forced focus projection does not force an AX frame write once `requestedFrames` already equals the target. Unlike the pre-async path, ordinary visible-window projection also skips previously requested frames, so stale physical geometry can survive Cmd-Tab and other corrective projections.
- Startup launches asynchronous transient-window detection but admits the startup full scan immediately. Periodic reconciliation no longer refreshes transient state at all; both differ from the pre-async force-refresh behavior.
- Full scans use one global state generation. An unrelated lifecycle event from one PID invalidates every healthy PID result and restarts the whole scan, allowing a noisy application to starve startup, logical-Space, or recovery reconciliation.
- Unavailable PIDs are represented by appending all known windows to the discovered-visible set. This preserves lifecycle state but falsely treats off-Space windows as currently visible and can corrupt logical-Space matching.
- `ManagedWindow.windowID` is immutable, so a window whose private ID lookup temporarily failed cannot receive the ID from a later successful worker snapshot despite the documented enrichment behavior.
- Lane coalescing marks queued jobs stale without removing them. Resize/move/focus bursts can accumulate arbitrarily many no-op jobs and main-actor callbacks before the latest job executes.
- A running `.cannotComplete` operation can reopen its PID circuit after `quiesceAllAndResetHealth` cleared health. The subsequent termination restoration batch can then be circuit-rejected without making its required final attempt.
- Raw asynchronous scan logging is emitted for every periodic/active scan instead of being signature-deduplicated. With debug logging enabled this produced a roughly 52 MB log and repeated synchronous main-thread file writes.
- The current application-pipeline liveness test only tests a hand-written closure-capture pattern, not the production `readApplication` callback chain, so it would not detect the weak-capture regression it claims to cover.
- Whole-read budgets can repeatedly restart from element zero. A sufficiently large but healthy app can therefore remain permanently undiscovered rather than making incremental progress.
- Focus-read staleness is guarded by frontmost PID and logical focus generation, but separate per-PID lanes allow an old read to become valid again after an A→B→A activation sequence unless each adoption request has its own global authority generation.
- Transient-window refresh has no independent completion deadline. If an underlying AX call exceeds the configured messaging timeout, activation and recovery completions can remain pending indefinitely.
- Intermediate successful application-read chunks can clear a PID's adaptive failure history before the whole read succeeds, defeating circuit backoff around a consistently failing later window.
- Replacing an active composite read without first finishing the old pipeline allows an already-delivered old callback to enqueue another chunk after the newer generation and supersede the replacement.
- Partial startup discovery can consume persistent layout/logical-Space restoration before later rotating chunks discover the remaining windows.
- A no-op command at the head of the deferred/recovery command queue can strand every command behind it because no layout completion triggers the next drain.
- The temporary keyboard-focus authority used for Miri navigation also suppresses authoritative NSWorkspace activation adoption, so Cmd-Tab shortly after a Miri focus command can focus the app physically while leaving its column parked until a second activation.
- The Cmd-Tab input fallback can supersede the immediate activation-focused read through the global adoption generation, then skip projection when logical focus is unchanged; the second Cmd-Tab probe finally projects the previously activated window. Command-window-switch probes must therefore be authoritative projection barriers too, and immediate fresh activation reads must not wait behind the transient refresh fan-out.
- Focused-fullscreen guards run before reconciliation attempts to restore a newly non-fullscreen snapshot, so the remembered fullscreen state suppresses the very scan that could clear it. The window remains absent until focus moves to a neighbor; exit restoration must run before re-evaluating the guard.
- Applications hidden before Miri starts are omitted from window enumeration. They still need observer registration, and an activation's post-transient lifecycle reconciliation must run even if focus moved elsewhere while the bounded transient refresh was in flight; otherwise newly shown windows can remain unknown indefinitely.

### Isolation and scheduling gaps

- Private window-ID resolution is required before some snapshots complete even though `ManagedWindow.windowID` is optional.
- `readApplication` is one coarse lane job that may perform many synchronous calls. A large but responsive application can monopolize its PID lane and delay same-PID interactive work.
- Full reconciliation and session recovery wait for every coarse application read, so a slow successful enumeration can delay recovery command replay.
- Circuit health records only the final operation result; a very slow successful composite operation is not treated as unhealthy.
- Several unused synchronous helpers remain available on the main actor and could accidentally reintroduce target IPC.

### AX calls allowed outside target-PID workers

The refactor should distinguish local/reference operations from target-app IPC. These may remain outside the worker transport unless testing proves otherwise:

- `AXUIElementGetPid`
- `AXObserverGetRunLoopSource`
- `AXValueCreate` and `AXValueGetValue`
- `AXUIElementCreateApplication` and `AXUIElementCreateSystemWide`
- `AXIsProcessTrusted*`
- Process-wide `AXUIElementSetMessagingTimeout`
- `CFEqual` and `CFHash` on AX references

Target reads, writes, actions, settable checks, observer registration, and private window-ID mapping must be worker-only.

## Implementation phases

### Phase 1 — Enforce one AX target-IPC boundary

- [x] Define one low-level AX execution boundary as the sole owner of synchronous target-app IPC in the interactive process, plus a worker-only cleanup transport.
- [x] Move raw target AX helpers behind that boundary and prevent main-actor call sites from accessing them directly.
- [x] Document the local/reference AX allowlist and the worker-only target-IPC APIs.
- [x] Add a source audit or CI check that rejects target AX APIs outside approved transport files.
- [x] Delete unused synchronous helpers from `MiriWindowLookup.swift`: `axString`, `axBool`, `axAttributeExists`, `isAXAttributeSettable`, and `axFrame`.
- [x] Delete the unused element-based `isManageableWindow(_:)`; retain snapshot-based classification only.
- [x] Remove synchronous AX frame writing from `LayoutWindowSystemAdapting`.

### Phase 2 — Remove main-actor private window-ID mapping

- [x] Stop calling `SkyLight.shared.windowID(for:)` from AX notification handling.
- [x] Seed notification handles with a known cached window ID when available and otherwise use `nil`.
- [x] Make `_AXUIElementGetWindow` resolution worker-only and optional.
- [x] Separate window-ID enrichment from required notification/focused-window snapshot completion where possible.
- [x] Ensure discovery, focus adoption, transient checks, and session recovery remain correct for windows whose ID is temporarily unavailable.
- [x] Keep unknown pointer-target recovery conservative when no safe ID mapping exists.

### Phase 3 — Add bounded asynchronous termination

- [x] Introduce an explicit termination restoration state/barrier.
- [x] Close AX admission and globally quiesce/supersede existing AX work before restoration begins.
- [x] Group final restoration by PID and submit it through independent workers.
- [x] Reset final-restoration PID health so every relevant app receives one bounded final attempt.
- [x] Batch `AXEnhancedUserInterface` handling once per PID rather than once per window.
- [x] Add a global termination deadline so multiple failures cannot block process exit indefinitely.
- [x] Integrate AppKit termination deferral (`applicationShouldTerminate` and termination reply) so the process exits only after success or deadline.
- [x] Route menu quit, AppKit termination, and signal termination through the same idempotent state machine.
- [x] Ensure late pre-termination AX completions cannot physically retile windows after restoration.
- [x] Report per-PID restoration success/failure so cleanup fallback decisions are authoritative.
- [x] Remove the restore document and stop the watcher only after successful restoration; retain fallback state on partial failure or timeout.

### Phase 4 — Repair crash and forced-exit restoration

- [x] Restore regular writing of the exit restoration snapshot before real layout frames are changed.
- [x] Update snapshots during layout projection and lifecycle/logical-context saves, and remove them when restoration is disabled.
- [x] Version the restore format while preserving backward decoding.
- [x] Store owner PID and tiled/floating kind with each restorable window ID.
- [x] Restrict cleanup AX enumeration to relevant owner PIDs.
- [x] Process relevant PIDs independently so one hung app cannot delay healthy restoration.
- [x] Apply viewport frames only to tiled windows.
- [x] Preserve floating-window geometry while normalizing transforms and levels.
- [x] Give cleanup restoration a hard overall deadline and guaranteed process exit.
- [x] Keep cleanup restoration idempotent when normal termination partially restored windows first.

### Phase 5 — Bound and subdivide composite AX work

- [x] Add whole-operation time budgets in addition to the global 250 ms per-call timeout for composite reads and observer registration.
- [x] Check the budget between application-window snapshots and supplemental reads.
- [x] Preserve known state when an application-read budget expires.
- [x] Split large application discovery into one-window lane chunks so interactive work for the same PID can run between chunks.
- [x] Keep observer registration bounded across its notification loop.
- [x] Keep private window-ID enrichment out of notification/focused-window barriers; lifecycle enumeration resolves IDs only in bounded worker chunks where model identity requires them.
- [x] Ensure a budget-expired PID is treated as unavailable without blocking full scan or session recovery.
- [x] Extend diagnostics with queue wait, estimated AX call count, operation duration, budget exhaustion, and termination-restoration outcomes.

### Phase 6 — Repair activation/startup projection and complete the regression audit

- [x] Restore corrective visible-window frame writes and unconditional focused-item force writes while retaining asynchronous per-PID execution.
- [x] Serialize startup and periodic reconciliation behind completed, current transient-window refreshes.
- [x] Replace global full-scan invalidation with per-PID stale-result handling and keep unavailable known windows out of the current visible signature.
- [x] Permit worker snapshots to enrich a known window whose cached private window ID is missing.
- [x] Physically remove superseded queued lane jobs and test bounded coalescing under bursts.
- [x] Reset/bypass circuit health after quiescence so every termination PID receives one final attempt.
- [x] Restore signature-deduplicated raw snapshot logging.
- [x] Replace the superficial pipeline-retention test with coverage of the production scheduling path.
- [x] Ensure large healthy applications make incremental discovery progress across bounded chunks/scans.
- [x] Add a global focused-adoption authority generation for cross-PID A→B→A stale-result rejection.
- [x] Add a bounded transient-refresh completion barrier.

- [x] Strongly retain each chunked application-read pipeline across enumeration and chunk callbacks until exactly one terminal result.
- [x] Add regression coverage proving an application-read pipeline remains retained across asynchronous callback handoffs.
- [x] Reverify startup full discovery constructs the model and projects existing windows.

- [x] Make frontmost application activation request an authoritative focused-window read even when lifecycle reconciliation is also pending.
- [x] Reveal and project the adopted column on Cmd-Tab even when it was already the logical active column.
- [x] Keep activation reconciliation frontmost-validated before it can adopt focus.
- [x] Reject delayed activation reads after the frontmost PID or focus generation changes.
- [x] Compare termination, crash restoration, focus, lifecycle, fullscreen, minimization, hiding, logical Space, snapshot, and session recovery semantics with the pre-refactor behavior.
- [x] Audit every AX symbol and helper call after implementation; classify every remaining exception.
- [x] Verify no target-app AX IPC occurs on the main actor.
- [x] Verify no cleanup or termination path serializes healthy PIDs behind a hung PID.
- [x] Update `README.md`, architecture, troubleshooting, snapshot, discovery, and restoration documentation.
- [x] Keep this temporary plan present and update its checkboxes throughout implementation.

## Manual acceptance criteria

The user must manually validate all relevant scenarios before this work can be accepted:

- [x] Starting Miri with existing manageable windows constructs and projects the saved/current layout.
- [x] Normal focus/layout remains responsive while one managed app is deliberately unresponsive.
- [x] Cmd-Tab to an app with a managed window reveals and moves the layout to the focused window, including when that window was already the logical active column.
- [x] Rapid Cmd-Tab changes cannot let a delayed activation read snap focus back to an older app.
- [ ] AXCreated, moved, and resized events from a hung app do not pause healthy-window navigation.
- [ ] Normal menu quit completes within the documented bound while one app is hung.
- [ ] Healthy tiled windows restore even when another PID times out.
- [ ] No late queued frame write retiles a window after exit restoration.
- [ ] AppKit quit and signal termination behave consistently.
- [ ] Forced termination invokes cleanup restoration from a current snapshot.
- [ ] Tiled windows restore to the intended viewport.
- [ ] Floating windows retain their frame while level/transform state is normalized.
- [x] Lock/unlock and sleep/wake recovery complete with a slow or high-window-count application present.
- [x] Queued recovery commands run only after current reconciliation.
- [x] Native fullscreen, minimize/deminimize, Cmd-H/show, app launch/termination, and logical Space behavior remain correct.
- [x] Snapshot and `off` animation strategies both remain correct.
- [ ] Repeated operation does not accumulate workers, retries, observers, restore processes, or pending commands.
